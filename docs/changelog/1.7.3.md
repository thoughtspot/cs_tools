### Check out the <span class=fc-green>highlights</span> of our latest CS Tools release!

A single-fix release. [`searchable metadata`][cst-tools-searchable-metadata] makes far fewer requests while it
collects permissions, so a large cluster no longer trips the __ThoughtSpot__ API rate limit partway through an extract.
__Nothing else changes: every command runs exactly as it did in 1.7.2.__{ .fc-purple }

!!! success ""

    === "Permissions in far fewer requests"
        The access phase used to send one `security/metadata/fetch-permissions` request per object. On a cluster with
        thousands of objects that is thousands of requests inside a couple of minutes, which crosses the limit of 50
        requests per second per Org that __ThoughtSpot__ 26.11 enforces, and the extract fails before it finishes.

        Objects are now looked up 25 at a time, the same bound the metadata search already uses. Six thousand objects
        take about 240 requests instead of 6,000, at the default concurrency.

        If the cluster answers with a rate limit anyway, __CS Tools__ waits as long as the response asks, up to 30
        seconds, and tries up to six times before it records that batch as failed. Every other transient error keeps
        its three attempts.

        No new flags and no schema change. Upgrade with `cs_tools self update`. Thank you to the community for the
        detailed report.

---

??? danger "Breaking Changes"

    None. The fix ships with tests that pin the batch size and the retry behavior.
