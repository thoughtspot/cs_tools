### Check out the <span class=fc-green>highlights</span> of our latest CS Tools release!

A single-fix release. [`searchable ts-ai-stats`][cst-tools-searchable-ai-stats] no longer stops when the window holds
a query that the external database rejected or timed out.
__Nothing else changes: every command runs exactly as it did in 1.7.3.__{ .fc-purple }

!!! success ""

    === "Queries that never finished are kept"
        When a query against the external database fails or times out, __ThoughtSpot__ records the query without a
        DB End Time. __CS Tools__ treated that end time as required, so a single such query anywhere in the requested
        window stopped the extract with a validation error before any row was written. On a busy cluster, a window of
        a few weeks nearly always holds one.

        Those rows are now stored with an empty end time, alongside their start time, status and error message, so
        the failures themselves become visible in the extract.

        No new flags and no schema change: the column was already nullable in every warehouse the syncers create.
        Upgrade with `cs_tools self update`.

---

??? danger "Breaking Changes"

    None. The fix ships with a test that feeds the transformer a row with no end time.
