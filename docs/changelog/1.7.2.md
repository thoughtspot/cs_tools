### Check out the <span class=fc-green>highlights</span> of our latest CS Tools release!

A focused release. Searchable gains an opt-in view of your Liveboard schedules, the TML library catches up with
__ThoughtSpot Cloud__, and two reported bugs are fixed.
__Nothing changes unless you ask for it: every existing command runs exactly as it did in 1.7.1.__{ .fc-purple }

!!! success ""

    === "Liveboard schedules in Searchable"
        [`searchable metadata`][cst-tools-searchable-metadata] can now extract your Liveboard schedules and their
        run history, so you can answer how many schedules exist, which are paused, which stopped running, and which
        ones fail.

        The extract is opt-in. Add `--include-schedules` to your existing command and nothing else changes.

        ```shell
        cs_tools tools searchable metadata --syncer "snowflake://..." --include-schedules --config ENV:
        ```

        - `TS_SCHEDULE` holds one row per schedule per extract date, so a schedule's history accumulates under any
          load strategy.
        - `TS_SCHEDULE_RUN` holds one row per run with its status and error detail. __ThoughtSpot__ keeps about 30
          days of run history, so a regular extract builds the longer record for you.
        - `searchable deploy` creates both tables and their joins to `TS_CLUSTER` and `TS_ORG`.
        - A page the cluster cannot answer logs a warning and the extract keeps what it already fetched.

    === "TML spec caught up with ThoughtSpot Cloud"
        __CS Tools__ now requires `thoughtspot_tml` 2.4.5, which was regenerated from the current __ThoughtSpot__
        spec. TML carrying `viz_style`, `author`, `obj_id`, `ai_tile` and the other recent attributes loads and
        deploys again, with no changes to your files.

        Upgrading to 1.7.2 with `cs_tools self update` pulls the new library in automatically.

    === "Fixes"
        - On Windows, a run with its output redirected to a file, such as a scheduled task or a CI step, no longer
          exits 1 after a fully successful extract. The phase markers in the log lines are plain ASCII now.
        - `scriptability checkpoint` exports each object once. An object published to several Orgs used to come
          out once per Org, under the same GUID. Thank you to the community for the report and the fix.
        - `cs_tools self sync` upgrades only the packages it names. It used to let the resolver move every dependency
          underneath them as well, which overrode the pinned command-line library and left every command failing on
          startup. If a sync already broke your installation, `cs_tools self update` repairs it.
        - New installations stay on SQLAlchemy 2.0. The Snowflake dialect does not support SQLAlchemy 2.1 yet, and
          an install made after its release could not connect to Snowflake at all.
